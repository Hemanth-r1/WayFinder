# WayFinder Firebase Backend Design

## Overview

Add real authentication and persistent data to WayFinder using Firebase Auth + Firestore. The app is currently 100% client-side with a fake auth dropdown and no data persistence.

## 1. Firebase Auth

- Email/password auth via Firebase Auth SDK
- Login screen rendered when no user is authenticated
- `onAuthStateChanged` listener drives the auth state
- First sign-up creates a `users/{uid}` document in Firestore
- Existing `RoleSelector` component becomes a profile widget (email + sign out)
- Role is read from Firestore `users/{uid}.role`, not local state

## 2. Firestore Collections

### `users/{uid}`
```
{ email: string, role: 'user' | 'supporter' | 'controller', createdAt: Timestamp }
```
- Read/write: only the owning user
- Admin can change role via Firestore console

### `routes/{routeId}`
```
{ userId: string, sourceNodeId: string, destNodeId: string,
  avoidCongestion: boolean, preferMainRoads: boolean, createdAt: Timestamp }
```
- Read/write: only the owning user
- autoId generated by Firestore

### `signals/{signalId}`
```
{ supporterId: string, nodeId: string, lat: number, lng: number,
  roadName: string, signalType: string, timestamp: Timestamp }
```
- Read: all authenticated users
- Write: users with role `supporter` or `controller`
- Real-time `onSnapshot` listener

### `overrides/{overrideId}`
```
{ controllerId: string, signalId: string, direction: 'N' | 'S' | 'E' | 'W',
  color: 'GREEN' | 'RED', active: boolean, expiresAt: Timestamp, timestamp: Timestamp }
```
- Read: all authenticated users
- Write: users with role `controller`
- Real-time `onSnapshot` listener

## 3. Security Rules

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users - only self-read/write
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // Routes - only self-read/write
    match /routes/{routeId} {
      allow read, write: if request.auth != null && request.auth.uid == resource.data.userId;
      allow create: if request.auth != null && request.auth.uid == request.resource.data.userId;
    }

    // Signals - all auth can read, supporters+ can write
    match /signals/{signalId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role in ['supporter', 'controller'];
    }

    // Overrides - all auth can read, controllers can write
    match /overrides/{overrideId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'controller';
    }
  }
}
```

## 4. Data Flow

- **Auth**: `onAuthStateChanged` → `useAuth` hook returns `{ user, role, loading }` → login screen or app
- **Routes**: UserPanel reads user's routes via Firestore query, writes on submit. No real-time needed (private).
- **Signals**: `onSnapshot` on signals collection. SupporterPanel writes new signals. All users see updates.
- **Overrides**: `onSnapshot` on active overrides. ControllerPanel writes. The engine applies overrides from Firestore state.
- **Engine overrides**: Engine reads override state from Firestore via the real-time hook, not from manualOverrideSignal calls.
